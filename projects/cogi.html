Overview

개요 · 왜 만들었는지

GitHub 저장소를 연동해 Pull Request 코드를 AI로 자동 리뷰받고, 반복적으로 발견되는 약점을 통계로 누적해 개인·팀의 성장 추이로 연결하는 개발자 코드리뷰 SaaS입니다.

Spring Boot 백엔드 + React(Vite·TypeScript) 프론트로 구성했고, 저는 회원 탈퇴·인증/보안·주간 성장 리포트·배포를 담당하며 API 30개를 구현하고 주요 시나리오를 단위 테스트로 검증했습니다.

My Work

담당 기능

  • 인증 / 보안 — JWT + HttpOnly 쿠키, GitHub·Kakao OAuth2, TOTP(RFC 6238) 2FA, 로그인 실패 잠금·비밀번호 재설정
  • 회원 탈퇴 — 팀장 권한 자동 위임·팀 해체 정책, 개인정보 익명화 기반 소프트 삭제

  • 배포 — Docker Compose 기반 AWS EC2 배포, 환경변수 분리·HTTPS 적용
Problem Solving

문제 해결

① 회원 탈퇴 — "지우는 기능일수록 남는 데이터를 먼저"
Problem팀장이 탈퇴하면 저장소를 관리할 사람이 사라지고, 팀을 함께 삭제하면 남은 팀원의 리뷰 이력이 모두 사라졌습니다.
Cause단순히 회원 상태만 변경하는 방식으로는 권한 공백과 데이터 손실을 동시에 막을 수 없었습니다.
Solution탈퇴자가 팀장인 팀마다 최선임 팀원에게 권한을 자동 위임하고, 팀원이 없을 때만 해체하도록 설계했습니다. 회원 정보는 물리 삭제 대신 닉네임·소셜·인증 정보를 비우는 익명화 소프트 삭제로 처리했습니다.
Result탈퇴 후에도 팀·리뷰 데이터 무결성을 유지했고, 해체된 저장소가 재연동을 거부하던 문제도 연동 정보·대기 초대를 함께 정리해 해결했습니다.
② 한 명의 실패로 멈추던 주간 리포트 배치
Problem주간 리포트 발송 중 한 사용자 처리에서 예외가 나면 배치 전체가 중단될 위험이 있었습니다.
Cause사용자별 처리가 하나의 흐름에 묶여 있어 예외가 그대로 전파됐습니다.
Solution사용자 단위로 예외를 격리해, 한 사용자가 실패해도 다음 사용자 처리가 계속되도록 했습니다.
Result일부 실패 상황에서도 리포트 발송 배치가 끝까지 완주하도록 안정성을 확보했습니다.
Why

기술 선택 이유

WHYJWT + HttpOnly 쿠키

기존 토큰 방식을 HttpOnly 쿠키 기반으로 전환해, JS로 접근할 수 없게 하여 XSS로부터 토큰 노출을 줄였습니다.

WHYTOTP 2FA

비밀번호가 유출돼도 계정을 지킬 2차 방어가 필요해, 표준(RFC 6238) 기반 TOTP 2단계 인증을 적용했습니다.

WHYDocker Compose + EC2

팀 전원이 동일한 환경에서 재현·운영할 수 있도록 컨테이너로 묶어 AWS EC2에 배포하고 환경변수를 분리했습니다.

WHYAI 프로바이더 추상화

특정 AI 제공자에 종속되지 않도록 리뷰 클라이언트를 멀티 프로바이더로 추상화해 교체 유연성을 확보했습니다.
